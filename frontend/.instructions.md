# Frontend Development Instructions - UI/UX Quality Assurance

You are developing a Next.js 16 + React 19 secondhand marketplace frontend with strict UI/UX standards.

## Critical Requirements

### 1. SPACING RULES (ABSOLUTE - NO EXCEPTIONS)

**When creating/modifying pages that use `PageShell` component:**
- ✅ Component automatically provides `padding: 40px 32px` - DO NOT override
- ✅ Content inside automatically gets proper spacing
- ✅ Headings get `margin-bottom: 28px` automatically

**When creating/modifying pages that use `<form>` or `<div className="field">`:**
- ✅ Every form field MUST be wrapped: `<div className="field"><label>...</label><input/></div>`
- ✅ Fields automatically get `margin-bottom: 16px` separation
- ✅ DO NOT add inline padding/margin that contradicts design tokens

**Pages Currently Using PageShell (8+):**
- `/listings/new` - Create listing form
- `/profile` - User profile page  
- `/inbox` - Messaging/inbox page
- `/dashboard/offers` - Transactions page
- `/profile/recycle-bin` - Deleted items
- Any future page with `<PageShell>` component

**Spacing Scale (Only Use These Values):**
```
4px    - Micro spacing (inside components)
6px    - Form label-to-input gap
8px    - Button gaps
12px   - Container padding
16px   - Form field margin-bottom ⭐ MOST COMMON
24px   - Card gaps
32px   - Section spacing
40px   - Page horizontal padding ⭐ CRITICAL
48px   - Hero section padding
```

### 2. COLOR CONTRAST RULES (WCAG AA COMPLIANCE - MANDATORY)

**Text Visibility Standards:**
- ✅ Large text (18pt+): Minimum 3:1 contrast ratio
- ✅ Normal text: Minimum 4.5:1 contrast ratio
- ✅ Test: Use browser DevTools > Accessibility panel

**Navigation Bar (`.nav-shell`) - FIXED PATTERN:**
```css
.nav-shell {
  background: var(--color-navy);           /* Dark #2d3250 */
  color: var(--text);                      /* Light #e8eef8 */
  border-bottom: 1px solid rgba(249, 177, 122, 0.2);
}
```
- ❌ DO NOT use `rgba(255, 255, 255, 0.82)` - causes invisibility
- ❌ DO NOT use light backgrounds with light text
- ✅ Dark backgrounds with light text = good contrast

**Form Elements - STANDARD PATTERN:**
```css
.field input {
  background: var(--bg-card);       /* Use design token */
  color: var(--text);                /* Dark text, high contrast */
  border: 1px solid var(--border);  /* Visible border */
}
```

**Always Use Semantic Color Variables:**
- ✅ `var(--bg)`, `var(--bg-card)`
- ✅ `var(--text)`, `var(--text-secondary)`, `var(--text-tertiary)`
- ✅ `var(--accent)` for interactive elements
- ❌ NEVER hard-code color values like `#2d3250` in component code

### 3. FORM DESIGN CHECKLIST (Before Every Commit)

- [ ] Every field wrapped in `<div className="field">`
- [ ] Form uses `<label htmlFor="id">` (accessibility)
- [ ] Visual gap between field groups (16px auto margin-bottom)
- [ ] Input height minimum 44px (touch target)
- [ ] Error messages have visible color (4.5:1 contrast)
- [ ] Focus state has visible outline (blue accent)
- [ ] All text readable on background (contrast test passed)
- [ ] No inline style padding overrides form field spacing

### 4. COMPONENT USAGE PATTERNS

**✅ CORRECT - Using PageShell:**
```jsx
import { PageShell } from "@/components/page-shell";

export default function NewListingPage() {
  return (
    <PageShell
      title="Đăng tin mới"
      description="Điền thông tin sản phẩm để bắt đầu bán"
    >
      <div className="field">
        <label htmlFor="title">Tiêu đề *</label>
        <input id="title" type="text" required />
      </div>

      <div className="field">
        <label htmlFor="price">Giá (VNĐ) *</label>
        <input id="price" type="number" required />
      </div>

      <button type="submit">Đăng tin</button>
    </PageShell>
  );
}
```

**❌ WRONG - Missing spacing/contrast:**
```jsx
export default function NewListingPage() {
  return (
    <div>
      <h1>Đăng tin mới</h1>
      
      <div>
        <label>Tiêu đề</label>
        <input type="text" style={{ marginBottom: 0 }} />
        
        <label>Giá</label>
        <input type="number" style={{ marginBottom: 0 }} />
      </div>
    </div>
  );
}
```
Problems:
- No padding around page content
- No gap between form fields  
- Inline styles override design tokens

### 5. CSS MODIFICATIONS RULES

**When Modifying `globals.css`:**
- ✅ Add new spacing values only to standardized scale
- ✅ Update `.page-shell`, `.field`, `.page-grid` only via PR
- ✅ Test on 5+ pages before merging
- ✅ Verify contrast with browser DevTools accessibility panel

**NEVER modify these without careful review:**
```css
.nav-shell { }      /* Navigation - affects all pages */
.page-shell { }     /* Page wrapper - affects 8+ pages */
.field { }          /* Form fields - affects all forms */
.page-grid { }      /* Section spacing - affects layouts */
```

### 6. RESPONSIVE DESIGN REQUIREMENTS

**Mobile-First Spacing (Tablet+ Media Query):**
```css
.page-shell {
  padding: 24px 16px;  /* Mobile - reduced padding */
}

@media (min-width: 768px) {
  .page-shell {
    padding: 40px 32px;  /* Tablet and up */
  }
}
```

- ✅ Test responsive at: 375px (mobile), 768px (tablet), 1024px (desktop)
- ✅ Form fields should stack on mobile, layout adjusts
- ✅ Padding reduces on narrow screens to avoid cramping

1. **Is this a new page?** → Use `<PageShell>` component
2. **Am I creating a form?** → Wrap fields in `<div className="field">`
3. **Am I changing colors?** → Use semantic variables (var(--color-navy), var(--text))

5. **Will this affect multiple pages?** → Run visual tests on 5+ pages

## Summary

**The 3 Rules (Remember These):**

1. **SPACING**: Use `<PageShell>` or add `padding: 40px 32px`. Form fields get auto `margin-bottom: 16px`
2. **CONTRAST**: Navy on light, or light on dark. Test with DevTools accessibility panel
3. **CONSISTENCY**: Follow globals.css patterns. Use design tokens. Don't hard-code values

**If a page feels "crammed" or "like Word document":**
- Check: Missing padding on page wrapper?
- Check: Form fields too close together (need margin-bottom)?
- Check: Headings bleeding into content (need margin-bottom)?

**When in doubt: Reference homepage (`/` route) - it's the quality baseline.**
